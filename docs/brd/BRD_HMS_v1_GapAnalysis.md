## Open Questions Before Implementation

1. **Opthal toggle vs. existing Optical module**: ✅ **RESOLVED** — Implemented as inline toggle on general Prescription form with `is_opthal` and `opthal_notes` fields. This allows ophthalmology-specific notes to be included in the same prescription document without requiring a separate Optical Prescription record.
2. **Institution model**: ✅ **RESOLVED** — Implemented using `institution_id` foreign key on Prescription model pointing to Hospital table. This allows dual-letterhead support by selecting which hospital/institution's letterhead to use for each prescription.
3. **Pharmacy/Opthal billing payment fields**: ✅ **RESOLVED** — Used the "add `paid_amount`/`balance_amount` directly to PharmacySale/OpticalSale" approach with shared `billing_queue_service` for payment calculation. This provides fast, isolated implementation with consistent behavior across both modules.
4. **Symptom master list**: ⚠️ **PENDING** — Symptom field added as JSONB array to Patient model, but master list seeding not yet implemented. UI component for multi-select with custom entries still needed.
5. **Queue Display data scope**: ✅ **RESOLVED** — Pharmacy column shows pharmacy dispensing queue, Opthal column shows optical dispensing queue. Doctor columns split walk-in queue between two doctors.
